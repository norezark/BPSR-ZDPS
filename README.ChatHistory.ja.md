# チャット履歴の保存・復元

ZDPSが受信したチャットを自動的にローカルSQLiteへ保存し、次回起動時に復元します。
導入以前に表示していた未保存チャットや、ZDPS停止中のチャットは取得できません。

## 保存場所と範囲

各実行ファイルのフォルダー内の `Data\ChatHistory\history.sqlite3` に保存します。
既存の設定ファイルは同じインストール内の `Data\Settings.json` のままです。遭遇履歴DBとは別ファイルです。
起動時の作業フォルダー（ショートカットの「作業フォルダー / Start in」）や、実行したユーザーのLocalAppDataには依存しません。

通常版とコピー版を別のフォルダーに置けば、同時に起動しても設定とチャットDBはそれぞれ独立します。
共有先を示すIDを設定ファイルに保存しないため、同じ設定をコピーしても同じDBに接続することはありません。
フォルダー全体をコピーした場合は、その時点の履歴ファイルもコピーされますが、以後の書き込み先はそれぞれのコピー内で独立します。
同じ実フォルダーへのショートカットやジャンクションは、別インストールではありません。

Windowsでこの.NET 9ビルドを検証した際、実行ファイルのフォルダーパスにセミコロン（`;`）が含まれると、
アプリの処理に入る前にCoreCLRの `0x80070057` エラーで起動できませんでした。実行ファイル／検証用フォルダーには
セミコロンを含めず、空白や日本語を含む通常のパスを使ってください。SQLiteのDBファイル名のセミコロンは、
別の保存・再接続テストで確認しています。実行ファイルのパス制限とDBファイル名の扱いは別です。

旧版がショートカットの「作業フォルダー」にある別の設定を使っていた場合、別の空でないDataフォルダーが見つかると起動を止めて確認を促します。設定JSONが同じでも、プリセットや遭遇DBが異なる可能性があるためです。
自動移行・上書きは行いません。どちらの設定を使うか確認し、バックアップしたうえで正しい設定一式を各インストールのDataへ移してください。
最初の試作版が使った共通LocalAppDataのDBも、自動では読み込み・移動しません。

- メッセージ本文だけでなく、送信者、チャネル、元のID、送信時刻、受信時刻、対象ID、元の通信データを保存します
- 個別チャットや表示フィルターで隠されたメッセージも、受信したものはローカルに保存されます
- 履歴は自動削除しません。遭遇履歴の保存日数設定も適用されません
- 「Messages shown per channel」は画面の表示件数だけを制限します。件数を増やすと、保存済みの古いメッセージが再読み込みされます
- タブ、ブロック、レベル、文字列、スタンプ非表示の各フィルターは復元したメッセージにも適用されます
- 復元でカウントダウン・警告などのライブ通知は再実行しません
- 同文の連続送信や、ゲーム側が同じIDを再使用したメッセージも別の受信として保存します

## 保存状態

保存はバックグラウンドで行います。通常終了時にキューを書き出します。
ディスク満杯、ファイルロック、書き込み不可、破損・未対応形式などが発生した場合は、チャット画面にエラーと未保存件数を表示します。
一時的な保存失敗は順序を保って再試行します。保存先が回復するまでZDPSを開いたままにしてください。

最大10,000件の待機キューが満杯になった後の新しいメッセージは保存できず、「rejected」に件数が表示されます。
このメッセージは表示に残る場合がありますが、終了後には復元できません。
また強制終了・電源断では、まだ書き込まれていない待機中のメッセージが失われる場合があります。
保存済みDBが読み込めなくても、自動で削除・初期化・置き換えは行いません。
「Reload saved chat history」で復元を再試行できます。

このDBは個人チャットを含む平文のローカルデータです。共有・アップロードは自動では行いません。
バックアップする場合は、それぞれのZDPSを正常終了した後に各インストールの `Data\ChatHistory` フォルダー全体をコピーしてください。
起動中はSQLiteの `-wal` / `-shm` も使われるため、DB本体だけのコピーは避けてください。

## 更新・ロールバック

- 通常版とコピー版の両方を、別々にバックアップしてください
- 実行ファイルを更新・戻す場合も、各コピーの既存設定一式と `Data\ChatHistory` を保持してください
- 配布物には設定の初期化ファイルやChatHistoryフォルダーを含めません。更新時に既存Dataフォルダー全体を削除しないでください
- 履歴機能のない旧版に戻した間も、ChatHistoryを残せば対応版へ戻した際に再利用できます。旧版の実ゲームでの互換性検証とは別です
- 保存先に書けない場合は画面に保存エラーを出し、他のコピーや共通のユーザーフォルダーへ勝手に切り替えません

## 検証

```powershell
dotnet run --project tests/ChatHistory.Tests -c Release
dotnet run --project tests/ChatHistory.IntegrationTests -c Release
dotnet run --project tests/InstallationSettings.Tests -c Release
dotnet run --project tests/FactorEnergy.Tests -c Release
dotnet build BPSR-ZDPS/BPSR-ZDPS.csproj -c Release
```

保存層テストは一時フォルダー内の合成データを使い、実際のチャットや本番DBには触れません。
統合テストは実際のChatManagerをリンクし、Windows UIだけを軽量スタブに置き換えます。
InstallationSettings.Testsは実際のアプリ本体を参照し、別プロセス・別フォルダーで実際の設定読み込み／保存と、タブ設定・履歴の独立性を確認します。
Windowsでの画面操作、実ゲームの受信、既存インストールへの展開後の起動確認は別途必要です。

Gitの所有者が一致しない作業フォルダーでは、公開スクリプトはそのまま失敗させます。
信頼例外は追加せず、所有者の一致する新しい作業フォルダーを利用してください。
